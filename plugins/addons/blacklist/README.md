# 彩虹易支付PRO公共黑名单插件

装在易支付这一侧：把站里拉黑的人、被投诉的订单报给公共黑名单平台；也把平台的黑名单下发到本站，
**在付款的时候把人拦住**。

## 一、文件放哪儿

```
站点根目录/
└── plugins/addons/blacklist/          ← 整个目录传到这里（addons 目录没有就自己建）
    ├── BlacklistPlugin.php            插件主类（含支付拦截那条中间件的注册）
    ├── info.json                      插件信息 + 配置项定义（后台那个配置表单就是按它渲染的）
    ├── install.sql / update.sql / uninstall.sql   建表 / 升级 / 删表
    ├── lib/Client.php                 平台接口客户端
    ├── lib/Service.php                上行：投诉、台账、同步（autoSync 就是"先拉后报"那一轮）
    ├── lib/Down.php                   下行：平台黑名单 → 系统黑名单表（支付拦截就在这儿）
    ├── cron/BlacklistSync.php         系统计划任务里那条 60 秒一轮的任务
    ├── middleware/Refresh.php         每个请求顺手同步一次的中间件
    ├── controller/Admin.php           后台接口
    ├── controller/Asset.php           后台页面的 JS 走这个路由吐出去
    ├── controller/Task.php            插件自备的计划任务地址（"访问URL"型部署用，可挂可不挂）
    ├── static/admin.js                后台页面
    └── README.md                      本文件（不想传也行）
```

不用往 `app/` 里放任何东西，也不用改任何现有文件。

## 二、安装

1. 把 `plugins/addons/blacklist/` 整个目录传上去（保持目录结构）。
2. 后台 →「插件管理」→ 找到「公共黑名单」→ **安装** → **启用**。
   - 列表里没有它的话，点一下「刷新插件列表」（扫盘登记）。
   - 安装会建四张自己的表（`blacklist_sync` 上报台账、`blacklist_log` 事件日志、
     `blacklist_entry` 平台黑名单本地镜像、`blacklist_state` 同步游标），不动系统原有的任何表。
   - 顺手往系统的计划任务表（`pre_crontab`）里写**一行**：「公共黑名单同步」，60 秒一轮，
     默认开着。这只是往表里插一条数据（跟把黑名单写进系统黑名单表是一个路子），
     装完你到「系统管理 - 计划任务」里就能看到它，跟系统自带那些任务一样能停、能启、能单独跑一次。
3. 装完去左侧「交易管理 - 公共黑名单」看一眼就行 —— 同步已经在自己跑了，不用你点。
4. 旧版本升级上来的：直接覆盖目录，然后在「插件管理」里点一次**更新**
   （会跑 `update.sql` 补建两张新表 + 补上那行计划任务）。
   要是「系统管理 - 计划任务」里没看到它（比如计划任务表本身还没有，老站升上来的），
   插件页「自动同步」卡片上有个「**加进系统计划任务**」按钮，点一下就好。

> 一级菜单没出现的话，把 `BlacklistPlugin.php` 里 `getAdminMenus()` 的 `'parent' => 'TradeManage'` 改成 `''`，
> 它会变成一个顶级菜单项。

| 配置项 | 说明 |
|---|---|
| **平台接口地址** | `https://yzf.aiapizz.com/api`（填到 `api` 这一层，结尾带不带斜杠都行） |
| **平台接口密钥** | 平台「用户中心」里那串 32 位密钥 |
| 请求超时 | 建议 3 秒左右。下行同步另有 2 秒的硬超时，跟这项无关 |
| 投诉处理时上报平台 | 开着的话，投诉进来就自动上报（第 1 件事）。**建议开** |
| 投诉上报天数 | 投诉上报用多少天，默认 7。平台单次最多计 180 天 |
| 同步时自动匹配投诉 | 开着的话，同步的每条会去本地投诉记录里对一遍，能对上就按投诉上报（带订单号和投诉原文），对不上就按普通黑名单报。**建议开** |
| 本地黑名单同步天数 | 同步时每条报多少天，默认 180（平台单次上限）。本地那条写了到期时间的按剩余天数报 |
| 同步跳过名单 | 这些内容不报给平台，逗号或空格分隔，账号和 IP 混着写也行。填测试账号、公司自己的 IP 这类。**上行和下行都认这个名单** |
| 每日自动同步 | 只关"每天那一轮兜底"。1.3 之后同步是 60 秒一轮自动跑的（系统计划任务），所以这项开着关着都有人报，开着多一层保险 |
| 每日自动同步最多几条 | 默认 50。定时任务有执行时间限制，50~200 之间比较稳 |
| 每日刷新台账状态 | 每天把报过的记录状态拉一遍，平台退回了能看出来 |
| 手动上报默认天数 | 页面上手动上报时的默认值，默认 7 |
| **下发拦截** | 支付拦截的总开关，**默认开**。关掉就只上报、不下发 |
| **付款路径同步间隔（秒）** | 默认 10。**这个数基本就等于"平台上新拉黑一个人，到本站拦住他的时间"** |
| **普通页面同步间隔（秒）** | 默认 30。有人访问站点就顺手同步一次，和上面那档共用同一个"上次同步时间" |
| **下发哪些类型** | 账号和 IP 都要 / 只要账号 / 只要 IP。选"只要账号"时，IP 条目仍会记在本地（插件页看得到），只是不写进系统黑名单表 |
| **被几家报过才下发** | 默认 1。填 2 就是"至少两个不同站点都报过"才下发，能少拦误报，代价是生效慢一点 |
| **复核间隔（秒）** | 默认 1800（半小时）。已下发的条目每隔这么久回平台核对一次状态（撤销 / 延长 / 过期） |

填完保存，去插件页「设置 → 连接与开关」点一下「**测一下连接**」验证地址密钥 ——
用的是系统里就有的路由，不用另外配伪静态。计划任务那行安装时就登记好了，见第五节。

## 四、那一页上有什么

页面刻意做得很薄：五张卡片、四个按钮，一眼看完。配置那些收进「设置」里折着，不点开不占地方。

**第一张卡：状态 + 立即同步**

- 一行数字：本站在拦多少条、平台有效多少条、上次同步是什么时候（前面那个状态标签写着
  "运行中 / 只上报不拦截 / 上一轮没连上平台 / 还没连上平台"）；
- **「立即同步」一个按钮干两件事**：
  - 往上：把本站黑名单里还没报过的报给平台。一次 50 条，连点几次、或者积压多的话这一趟会连着报几批
    （最多几秒）；没报完会告诉你"还剩几条，下一轮接着报"。
    **已报过的会跳过** —— 平台的天数是从"当前剩余"往后接的，同一个内容重复报会越叠越长；
  - 往下：马上去平台拿最新的黑名单、写进系统那张黑名单表（也就是拦人的那一步）。
  - 顺序是**先拉后报**：这样刚拉下来的条目已经躺在本地表里了，上报那趟会认出来跳过，
    不会把我们拉下来的东西又原样送回平台去。
  - 计划任务、任务地址、这个按钮走的是同一套代码（`Service::autoSync()`），
    所以不会出现"手动点行、自动跑就是不行"这种没法查的问题。
- 底下那行小字是「自动同步到底有没有在跑」的证据：最近 24 小时同步了几轮、下一轮最晚多少秒后、
  上一轮的结果。**这里一直显示 0 轮才需要管**，去第二张卡看看。
- 平时不用点这个按钮，只有"我刚在平台上拉黑了谁、想马上确认本站也拦上了"才需要。

**第二张卡：自动同步** —— 同步怎么自己跑起来、跑起来了没有、坏了怎么办：

- 系统计划任务里那条 `blacklist_sync` 在不在、开着没有、上次什么时候跑的、跑成没跑成
  （失败了会把系统记下的报错原样显示出来，一眼知道卡在哪）；
- 系统是「Swoole 守护进程」还是「访问URL」模式 —— 守护进程模式下站长什么都不用配；
- 「访问URL」模式下，这里给出一条**插件自备的任务地址**（`你的站/addon/blacklist/task?key=…`），
  复制到宝塔 →「计划任务」→ 访问URL、执行周期 60 秒就行。它不依赖系统怎么解析插件的任务类，
  什么部署方式都保证能用；旁边还有「换一把密钥」；
- 表里没有那条任务的时候（老站、或者被谁删了），这里会有个「**加进系统计划任务**」按钮，点一下就补上。

**第三张卡：手动查一条** —— 看某个账号 / 手机号 / IP 现在在平台上的状态、累计多少天、什么时候到期。

**第四张卡：手动报一条** —— 跟订单无关的拉黑（你自己判断这个人有问题），填天数直接报给平台。

**「设置」（折起来的，平时不用点开）**

| 折项 | 里面有什么 |
|---|---|
| 连接与开关 | 地址、密钥、各档间隔、各个开关，一眼看全；还有一个「测一下连接」。**改还是要去「插件管理 → 配置」改**，这里只是给你看一眼 |
| 维护 | 「清空平台已下发条目」：只删插件写进去的那些行（备注带 `公共黑名单#`），你自己拉黑的人一个不动 |

台账、日志、最近下发那些表以前都堆在这一页上，现在拿掉了 —— 细节本来就在系统自己的
「交易管理 - 黑名单管理」里（那些行就是插件写进去的），要看排队状态就看那一行数字。

## 三、卸载

后台「插件管理 - 公共黑名单 - 卸载」：

- 删掉 `blacklist_sync`、`blacklist_log`、`blacklist_entry`、`blacklist_state` 四张自己的表；
- 把系统计划任务里那条 `blacklist_sync` 一起删掉（只认 `task` + `plugin` 都对得上的行，
  绝不碰系统自己的任务）。不删的话它每 60 秒失败一次，没必要留着；
- **系统原有的黑名单表一个字都不动** —— 包括我们下发进去的那些行。
  卸载脚本是 SQL，只能按备注前缀删，但万一你自己手抄过一行备注长得一样的，删错了就是删你的数据，
  所以一条都不删。想清干净：**卸载前先在插件页「设置 → 维护」里点一下「清空平台已下发条目」**；
- 如果为了「访问URL」模式在宝塔里挂过插件那条地址，记得去宝塔把那条任务删掉
  （留着也行，插件卸了那条地址就是 404）；
- 系统文件从头到尾没被改过，所以**卸载之后不用恢复任何东西**；
- 平台上已经报上去的内容不会因为卸载而消失，那是独立的一份数据，要撤得去平台那边操作。

## 四、常见问题

**投诉进来了，平台那边没收到**
1. 先看插件配置里「投诉处理时上报平台」是不是开着；
2. 再点一下插件页的「立即同步」，结果那一行会写清上报成功几条、失败几条（失败原因也在里面）；
3. 还有一种情况：这笔投诉**没有关联真实订单**，或者订单里没有买家账号/手机号/IP
   —— 平台只收"有真订单"的投诉，这种情况插件会记一条"未上报"，不会硬编数据上去。

**投诉上报没触发，但我想赶紧把人报上去**
去插件页点「立即同步」。投诉会自动拉黑的话，
本地黑名单里已经有这个人了（备注是"投诉自动拉黑"）；开了「同步时自动匹配投诉」，
同步时还能把对应的投诉记录匹配上，照样按投诉上报。

**平台上刚拉黑一个人，本站多久能拦住**
看「付款路径同步间隔」（默认 10 秒）。想马上确认，去插件页点「立即同步」，
然后到「交易管理 - 黑名单管理」里搜一下：能看到备注为 `公共黑名单#编号` 的那一行就是拦上了。

**系统「黑名单管理」里突然多了一堆行，是不是被入侵了**
不是，是平台下发的，备注都写着 `公共黑名单#编号`。不想要就在插件配置里把「下发拦截」关掉，
再去插件页「设置 → 维护」点一次「清空平台已下发条目」。插件页第一张卡上那行数字（"本站在拦 N 条"）
就是这件事的进度。

**我只想上报，不想让平台的黑名单加到我站里来**
把「下发拦截」关掉就行。上报照旧，本地一条都不会写。

**「系统管理 - 计划任务」里没看到「公共黑名单同步」**
1. 先去插件页「自动同步」卡片看一眼，那里直接写着它在不在；
2. 不在的话点那上面的「**加进系统计划任务**」按钮，它就会补上一行；
3. 还不行就看看系统的计划任务表（`pre_crontab`）本身是不是还没有 —— 那是老版本系统才有的情况，
   不影响功能，插件页第二条路（自备的任务地址）照样能把自动同步跑起来。

**系统是「访问URL」那种计划任务方式（没有 Swoole 守护进程）**
把插件页「自动同步」卡片里那条地址复制到宝塔 →「计划任务」→ 任务类型选"访问URL"、周期 60 秒。
不用管系统计划任务里那一行，两边一起用也不会打架（同一把锁）。

**点「立即同步」提示"下发：××刚跑过 / 正在跑"**
说明另一路（60 秒的计划任务、或者刚好有一个访客的请求）刚同步完。
按钮是**强制**跑一轮的，这种提示只会在"别人正拿着锁"的时候出现，等一两秒再点就行。
上面报上去的那一半不受影响，照样会跑。

**平台上的地址改了 / 密钥轮换了**
到插件配置里改一下，保存即生效（插件配置有缓存，保存时框架会自己清）。

**同步的时候提示「还剩 N 条」**
一轮最多连着报几批、每批 50 条（防超时）。**不用管它** —— 60 秒后的下一轮接着报，报完为止；
着急的话再点一次「立即同步」，它会在这一趟里接着往后报。

**计划任务那条地址会不会被人拿去乱用**
不会。它必须带插件生成的那把密钥（长度、字节都比对，不是"看一眼像不像"），
而且这条地址本身**不接受任何参数、不读任何输入、不返回任何配置** ——
就算密钥泄漏了，别人能做的也只是"替你多拉几次黑名单"，反而没坏处。
不放心就点「换一把密钥」，然后把宝塔里那条地址改成新的。

**我不想把某些人报上去 / 也不想拦某些人**
填进「同步跳过名单」，上行不上报、下行不下发（手动上报不受这个限制）。

## 九、升级、以及每个版本改了什么

### 怎么升级

1. **先备份**（站点文件 + 数据库，老规矩）；
2. 把新版本的 `blacklist` 目录**整个覆盖**掉站点里的 `plugins/addons/blacklist/` —— 不用先卸载；
3. 到后台「插件管理」找到「公共黑名单」，点一次「**更新**」，系统会把这一版带的 `update.sql` 整跑一遍；
4. 回插件页看第一张卡（本站在拦多少条、上次同步时间），数字是动的就没问题。


### 版本更新

| 版本 | 这一版改了什么 |
|---|---|
| 1.0 | 第一版，只有「上报」那一半：投诉处理时上报、本地黑名单补报。两张自己的表（`blacklist_sync` 台账、`blacklist_log` 日志） |
| 1.1 | 补上「下发」那一半：把平台的黑名单写进**系统自己那张黑名单表**，付款时由系统拦住。加 `blacklist_entry`（本地镜像）、`blacklist_state`（游标和节流）两张表 |
| 1.2 | 插件页做薄；加了**插件自备的计划任务地址**（`addon/blacklist/task?key=…`），给「访问URL」型部署用。没有新表、没有新字段 |
| 1.3 | 同步彻底自动：把「同步」这条任务登记进**系统自己的计划任务表**（`blacklist_sync`），30 秒一轮；插件页重写了一遍（原来那版在真机上打不开） |
| 1.4 | 自动同步从 30 秒放宽到 **60 秒**（按钮点下去照样立刻跑，间隔管的是「自己跑」那一路）；插件页重画、说明精简、手动查询只留账号 / IP；页面样式改成运行时插进 `<head>`，服务器上一个文件都没多 |

当前版本看后台「插件管理」列表里的版本号（也就是 `info.json` 里的 `version`）。
