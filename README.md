# cccyun · 易支付 PRO 插件

这里是**披萨插件**（官网 <https://yzf.aiapizz.com>）自己做的易支付 PRO 扩展插件仓库：
一个插件一个目录，每个插件**自带一份 md 文档** —— 怎么装、怎么升级、怎么用、卡住了先看哪儿、
每个版本改了什么，全在那一个文件里，跟着插件一起发给站长。

这个仓库还有一半用途更重要：**教你怎么给这套系统写插件**。系统给插件留了哪些口子、
`info.json` 每个字段什么意思、后台页面和计划任务怎么写、哪几件事一定不能做，
都写在 **[插件开发指南](docs/plugin-dev.md)** 里 —— 本仓库的插件就是照着它写的，
`plugins/addons/blacklist/` 是最完整的一个例子，可以当范本对着看。

## 装一个插件（三步）

1. 从官网插件页 <https://yzf.aiapizz.com/plugins.php> 下载 zip，解压出来就是一个插件目录（例如 `blacklist/`）；
2. 把它传到站点根目录的 `plugins/addons/` 里，回后台「插件管理」点一次「刷新插件列表」；
3. 列表里找到它 →「**安装**」→「**启用**」→「配置」里把该填的填上。

**升级**：把新版本的目录整个覆盖上去，再到「插件管理」点一次「更新」—— 系统会把这一版的
`update.sql` 跑一遍（全是能重复执行的语句，多点几次也不会有事）。

装、升级、卸载、每一项配置什么意思、出问题先看哪儿 —— 都在**那个插件自己的 README** 里，装之前扫一眼。

## 目录约定

```
plugins/addons/<插件名>/          ← 目录名就是插件名
├── <插件名>Plugin.php            插件主类（继承系统的 app\common\BaseAddon）
├── info.json                     插件信息 + 后台配置表单的定义
├── install.sql                   安装时执行（建表、登记计划任务；表名写 pre_）
├── update.sql                    升级时执行（要能反复跑）
├── uninstall.sql                 卸载时执行（自己的东西带走，站长的数据不动）
├── README.md                     ← 这个插件唯一的一份文档
├── controller/                   后台接口 / 公共路由的控制器
├── cron/                         给系统「计划任务」用的任务类
├── lib/                          业务逻辑
├── middleware/                   路由中间件（需要蹭每个请求时才用）
└── static/                       后台页面的脚本
```

## 所有插件共同遵守的几条

- **不修改系统的任何文件**，只走系统本来就留给插件的扩展点；找不到口子的地方（比如支付链路），
  就换思路把自己变成**数据**，让系统自己的代码去读（公共黑名单就是这么拦人的）；
- **不抛异常**：钩子、中间件里出任何事都自己兜住 —— 插件出问题不能连累站长下单，
  也不能打断系统的投诉流程和定时任务；
- **只建自己的表**（表名一律写 `pre_`），系统原有的表只读；卸载时自己的表、自己登记的计划任务都带走；
- PHP 8.0 以上、MySQL 5.7 / 8.0。
