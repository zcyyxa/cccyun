# 彩虹易支付 PRO 插件仓库

[aiapizz.com](https://aiapizz.com)（披萨插件）出品的易支付 PRO 插件，全部放在这里：**一个插件一份源码、一份使用文档**。

**这些插件一个系统文件都不改。** 只挂系统本来就留好的插件扩展点 —— 装上去、卸下来都不会在别处留下痕迹，
系统升级不会把它们覆盖掉，卸载之后也不用恢复任何文件。

## 装法（所有插件都一样）

1. **下载** —— 官网插件页拿 zip，或者从本仓库取 `plugins/addons/<插件名>/` 这个目录。
2. **传** —— 把**插件目录本身**（例如 `blacklist/`）整个传到站点根目录的 `plugins/addons/` 下面；
   没有 `addons` 目录就自己建一个。**别多套一层**（`plugins/addons/blacklist/blacklist/` 是错的）。
3. **装** —— 后台 →「插件管理」→「刷新插件列表」→ 找到它 → **安装** → **启用**。
4. **配** —— `插件管理 → 配置` 里填接口地址、密钥、开关。**所有插件都这样，代码里不写死任何一项配置。**

卸载也在同一个地方（「插件管理 → 卸载」）：插件自己的表、登记进系统的那条计划任务会一起清掉，
**系统原有的表和文件一个字都不动**。

升级、列表里找不到它、安装报 SQL 错这些，看 [docs/install.md](docs/install.md)。

## 目录约定

一个插件一个目录，目录名就是插件名（和它 `info.json` 里的 `name` 一致）：

```
plugins/addons/<插件名>/
├── <插件名>Plugin.php    插件主类（挂扩展点、注册路由和中间件）
├── info.json             插件信息 + 配置项定义 —— 后台那个配置表单就是按它渲染的
├── install.sql           安装建表      update.sql 升级      uninstall.sql 卸载
├── controller/           后台页面和接口
├── cron/                 交给系统计划任务跑的东西
├── lib/                  业务逻辑
├── middleware/           路由中间件（需要抢实时的插件才有）
├── static/               后台页面的 JS / 样式
└── README.md             这个插件的使用文档：装哪儿、怎么配、原理、常见问题
```

新插件照这个来：**一份源码 + 一份 README**，然后在上面那张插件表里加一行。

## 所有插件共同遵守的几条

- **不改系统文件**：不往 `app/`、`public/` 里塞东西，只用系统留给插件的扩展点。
  所以系统升级不会把插件覆盖掉，也不存在「升级完插件悄悄失效」这种查不出来的问题。
- **配置全在后台**：地址、密钥、天数、开关都在插件配置里，代码里一处都不写死。
- **写进系统的数据都带标记**：比如公共黑名单下发的行，备注是 `公共黑名单#编号` ——
  在系统自己的界面里看得见、删得掉，插件不会偷偷把它改回来。
- **能自己跑就不用人点**：同步、上报这类活交给系统的计划任务；后台那个按钮只是「我现在就想看看」的入口。

## 兼容性

- **系统**：彩虹易支付 PRO（ThinkPHP 内核 + Swoole 守护进程），需要系统带 `plugins/addons/` 插件机制和「插件管理」。
- **环境**：PHP 8.0 以上；MySQL 5.7 / 8.0，utf8mb4。
- 计划任务表（`pre_crontab`，系统的 `update5` 之后才有）缺失的老站，插件会自动走「访问URL」那条路，功能不受影响。
